      About this advisor, and what it does not model

      Every rule on partitioned tables was observed on a lab copy of a 24-month SALES table on Oracle 19.27, or comes from the 19c documentation; each finding says which, and says inferred when a combination was not run. The rules on plain tables, histograms, indexes and invalidation come from the 19c SQL Tuning Guide and the DBMS_STATS reference. The lab log is in docs/lab-observations.md.

      • Blocks are estimates using average partition size. Row samples are costed as full passes; histogram samples, segment allocation and index work can make actual I/O differ. The collector uses the largest partition change percentage for all changed partitions, so a mix of fresh and stale partitions can overestimate reads.
      • The automatic job is inferred from schema GATHER AUTO tests on 19.27. The real nightly task was not run in that lab. AUTO_CASCADE index counts are observations, not a guarantee that every index is always gathered.
      • Unverified combinations include force with individual partition locks, synopsis format migrations, and new histogram or column-group work under the automatic job. Non-incremental APPROX_GLOBAL AND PARTITION aggregation is represented by an upper bound.
      • Subpartitions. With GRANULARITY AUTO a composite table keeps partition statistics and partition synopses. In the lab, DML in one of four hash subpartitions made the whole parent partition read again.
      • Partition exchange. The gather after an exchange reads nothing only if the empty partition was gathered first, the staging table has a table-level synopsis (INCREMENTAL TRUE, INCREMENTAL_LEVEL TABLE) and both sides have the same histograms. Model the staging table as a plain table here.
      • Degree and concurrency change how long a gather takes, not what it reads. They are shown, not modelled.
      • Real-time and high-frequency statistics, online statistics for loads are other mechanisms; this page models one gather and the nightly job.
      • Other patch levels. Lab observations are from 19.27 and may vary across 19c release updates. REPORT_GATHER_TABLE_STATS reports affected objects without collecting statistics; it does not measure physical reads. Its 19c signature has no OPTIONS argument, so a GATHER AUTO call cannot be reproduced exactly by this table report.
      Written for Oracle Database 19c. A companion to Optimizer Statistics, explained. No server, no tracking: everything runs in this page.
